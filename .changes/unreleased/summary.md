`cpctl` now rides out brief outages instead of failing the step: it retries GitHub OIDC token fetches and control plane requests with backoff on network errors, 429 and 5xx for about half a minute, and keeps sending the current token until its expiry while a refresh fails. A job submission is retried only with the `Idempotency-Key` that `cpctl` sets inside GitHub Actions, so a retry never starts a second job. The guide also shows how to test a deployed control plane on its host before any workflow calls it.
