The composite action now runs only released binaries: instead of installing Go and building `cpctl` on every step, it downloads the `cpctl` of the release it is pinned to, checks it against the release's `SHA256SUMS` and that it reports that release's version, which takes about a second. Pin it to a release tag, or to the commit SHA a release tag points at; a workflow using `@main`, any other SHA or a local `./action` now fails with an error naming what to pin instead. Workflows pinned to `v0.1.0` are unaffected until they move their pin to this release.
